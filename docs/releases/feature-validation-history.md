## Plan 与插话

### 首选：零模型 token 的自动化验收

在仓库根目录运行：

```sh
pnpm test
pnpm test:e2e --grep 'automatic native delegation|reviews, edits|steers the active|retains rejected steering'
```

如果在构建时遇到 `vite: exec: node: not found`，先运行 `command -v node`。独立安装的 pnpm 能运行，并不代表子进程能从 PATH 找到 Node。本机 Apple Silicon Homebrew 的 Node 位于 `/opt/homebrew/bin/node`，可用下面的命令临时补齐 PATH，再运行验收：

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm test:e2e --grep 'automatic native delegation|reviews, edits|steers the active|retains rejected steering'
```

这个写法只影响本次命令，不修改全局 shell 配置。如果该路径下也没有 Node，需要先安装 Node 或将实际 Node 安装目录加入 PATH。

这些用例用临时数据库和确定性的 CLI 替身启动真实 Electron，不连接模型、不使用真实登录、不修改正式会话。前一条覆盖服务边界；后一条验证：

- Codex／Grok 不需要子代理按钮，底座发送的委派活动与结果正常展示并保存。
- 原生计划卡片可修改，版本递增；刷新后仍在；批准后仅执行修改后的正文，并恢复执行权限。
- “立即发送”留在当前回合，不产生队列项；刷新后显示接收状态。
- 插话模式不匹配时拒绝并保留输入；底座断连时显示结果未知、不自动重试。

截图写入 `test-results/native-plan-review.png`、`native-steering.png` 和两个底座的 `*-subagents.png`。测试替身验证的是 Moose 的接入与界面，不能证明某个真实模型一定会主动委派。

### 可选：实际安装包的最小冒烟

0.8.0 已用真实 Codex 验证过 Plan、批准执行和插话，通常无需重复消费额度。若想自行确认，选择最低推理强度和自己可用的低成本模型，使用空临时目录，避免扫描现有大项目。

1. 输入 `/plan`，选择计划模式，再发送：
   > 只制定一步计划：新建 hello.txt，内容为 OK。无需澄清，不读取其他文件，不执行，计划限一句话。
2. 应看到计划卡片，目录中尚无 hello.txt。点击“修改计划”，把内容改为 HELLO，保存并刷新，确认版本增加且正文保留。
3. 点击“批准并执行”，检查 hello.txt 内容为 HELLO，且不能再次批准同一版本。

这需要一次规划、一次执行，具体费用取决于模型、上下文及工具使用，不承诺固定 token 数。无需开启 Goal，也无需为测试强制创建子代理。

插话最省成本的验证方式仍是上面的自动化用例。真实验证可等下一次正常 Codex 任务运行时发送“最终回复请用中文，限三句话”，点击“立即发送”；应显示已加入当前回合，队列不增加。若任务已结束，明确拒绝属于正常竞态，输入应保留。不要为了测试反复让模型长时间运行。

不要默认运行 `scripts/check-native-workflows.ts`：它会调用真实模型，适合底座升级后需要重新核查协议时使用。

## 原生历史与子代理

已纳入 0.9.0 及后续安装包。入口是项目右上角的“原生会话”，子代理活动中的“打开子代理”打开独立面板。

### 最低成本验收

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm test:e2e --grep 'imports paginated|replays Grok|opens child history'
```

这三条测试启动真实 Electron、临时数据库和模拟 CLI，不连接真实模型、不消耗模型 token：

- 原生列表和正文分页、重复导入、重载后关联不丢、按回合分叉及来源记录、等待压缩完成事件。
- Grok 历史回放导入；分叉和压缩按钮不可用。
- 子代理历史独立展示、发送与停止只针对子线程、未知线程拒绝、审批继续归属于父会话。

服务与协议单测另外覆盖跨项目拒绝、分页失败不产生半份导入、循环游标、操作幂等、断连结果未知、请求 ID 冲突、重启不重放、旧协议版本、子线程完成不完成主任务。

### 自己点一遍

1. 在当前项目点“原生会话”，预览一条已有 Codex／Grok 历史，再点“导入或打开会话”。第二次导入应打开同一条 Moose 会话。
2. 在空闲的 Codex 会话打开同一面板，选择用户回合，点“从所选回合分叉”。新会话显示来源 ID 和分叉点；原会话不变。**这不会隔离或回滚项目文件**。
3. 在已有子代理活动中点“打开子代理”，查看父线程、原生状态、模型和历史。父任务仍活动且底座允许直接输入时才可发送；停止只中断子线程的活动回合。底座接收请求不代表子任务已经完成。
4. “压缩原生上下文”会请求底座压缩，可能消耗模型 token；为了省额度，可以跳过手动压缩，用上述模拟测试验收状态流程。真正压缩完成前项目保持互斥，关闭面板不会停止压缩。

导入和分叉的历史记录是导入时的快照；以后用外部 CLI 写入的内容不会自动同步到 Moose 时间线。可从原生历史面板重新读取最新内容，重复导入不会覆盖已有本地记录。原始附件只保留类型占位；不复制底座私有附件文件。

### 原生接口核验记录

2026-09-19，在本机用以下命令验证，只输出计数和能力，不输出对话正文，也不发送 prompt：

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm exec tsx scripts/check-native-sessions.ts
```

| 底座 | 本次真实验证 | 边界 |
| --- | --- | --- |
| Codex 0.155.1 | 握手版本、`thread/list`、`thread/read`、`thread/items/list`，正文首批 40 项并返回后续游标 | 分叉、压缩与子代理控制的变更流程通过协议 fixture 验证；本轮没有消耗模型额度做真实压缩或新增委派 |
| Grok 1.0.34 | 握手声明 list/load；`session/list`、`session/load` 回放 | 不提供原生分叉、压缩或结构化子代理控制；ACP 分块按相邻角色合并，不宣称精确回合 ID |
| Pi | 无对应 adapter 能力 | 显示不支持 |

Codex 入口要求握手版本符合已核验的 0.155+ 协议。版本门槛不是所有未来版本的兼容保证；实际接口拒绝会直接显示错误。Grok 按握手 capability 开放历史入口。

Codex `thread/resume` 只是加载会话，不等同于恢复关闭的子任务，因此恢复按钮禁用并解释原因，请让主代理使用原生恢复工具。子代理控制依赖父任务所属的活动连接，便于将审批准确路由回父会话。父任务结束后历史仍可读，控制不再开放。

### 故障和持久化

- 导入按真实目录校验，全部页面读取成功后一次落库，拒绝把别的项目历史绑定到当前项目。
- 分叉／压缩／子代理控制先持久化请求 ID；底座拒绝和连接断开分别记录。未知结果和应用重启都不会自动重发。
- 分叉返回 native ID 后先保存记录，再导入正文；若正文读取失败，可用记录中的 ID 从原生历史重新导入。
- 压缩等待 `contextCompaction` 和对应 `turn/completed`；回执、其他线程完成或中断都不算成功。活动 Goal 需先暂停，防止加载时继续执行目标。
- 数据库升级到 schema 4 保存来源；旧版应用会拒绝读取新版数据库。安装包发布时应保留升级前备份。
- 操作互斥只覆盖 Moose 自己的项目任务；同时在外部 CLI 修改同一会话不受 Moose 锁控制。

## Worktree

已纳入 0.9.0 及后续安装包。入口是项目右上角的“独立工作目录”。

### 最低成本验收

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm test:e2e --grep 'isolates agent writes|two isolated conversations'
```

使用真实 Electron、真实临时 Git 仓库和模拟代理，**不消耗模型 token**。覆盖隔离写入、会话目录中的 diff、合并预览与提交、保留与清理，以及同项目两个会话同时运行。

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm exec vitest run tests/unit/worktrees.test.ts
```

额外覆盖同目录串行、引用搜索范围、未跟踪／忽略文件保护、未合并提交保护、活动／排队任务保护、过期合并预览、冲突跨重启恢复、解决并暂存、中止合并、符号链接替换、重复创建和创建失败恢复。

### 使用流程

1. 添加 Git 仓库根目录为项目。打开“独立工作目录”，输入起始 ref（默认 `HEAD`，也可用分支、tag、commit）和新的分支名，点击“创建隔离会话”。创建新的空会话和受管 Git worktree，不改变原会话的 native ID 或目录。
2. 在两个不同工作目录的会话分别发送任务，两者可同时执行。同一目录中的会话仍串行；底座自行创建的子代理仍由底座管理。
3. 当前会话的文件引用、项目 skills、执行、编辑器／Finder、Git diff、原生历史与显式原生分叉均跟随会话目录。项目根目录仅用于项目归属和默认合并目标。
4. 完成修改后在相应工作目录提交代码。通用暂存／提交界面属于第四阶段，本阶段只提供合并专用的冲突暂存及合并提交。
5. 回到“独立工作目录”，刷新状态，检查目标路径、目标分支、两端 commit 和 diff，再点击“准备合并到项目”。目标固定为项目根目录当前检出的分支；本阶段不提供任意目标分支选择器。
6. 干净合并也不会立即提交。检查暂存后的 diff，点击“提交已审阅的合并”。如有冲突，点击“在编辑器中打开合并目标”，编辑冲突文件，逐一点击“已解决并暂存”，然后完成合并；也可显式中止。
7. 工作目录保持在磁盘上，不自动删除。“保留工作目录”会进一步禁用清理按钮。允许清理后，只有空闲、无排队任务、无未提交／未跟踪／忽略文件、无未合并到当前项目分支的提交时才允许清理。清理保留分支和聊天记录，不把旧会话悄悄切回项目根目录。

### 恢复与限制

- 受管目录位于 Moose 数据目录的 `worktrees/<projectId>/<worktreeId>` 下；数据库 schema 5 保存工作目录记录和会话关联。会话删除后目录仍受项目管理；项目删除前需要清理受管目录。
- 创建和清理先记录意图再调用 Git。打开状态面板时核对磁盘与 Git 注册，应用重启不自动再次创建、删除或合并；失败记录可检查和清理。
- 合并期间两个相关目录停止接收新任务，其他 worktree 可以继续运行。冲突与合并状态落库；重启后可检查并继续或中止。
- 来源、目标 commit／分支或暂存内容改变后，过期预览不能直接继续提交。异常的外部 Git 状态会拒绝操作并保留现场。
- 未提交的项目修改、依赖、忽略文件及聊天历史不会复制到新目录。需要在新目录自行准备依赖；例如 `node_modules` 会阻止清理，避免自动删除用户未检查的文件。
- 不支持把已有会话原地搬到另一目录、自动拷贝脏文件、任意目标 worktree 合并或自动删除分支。项目必须是已经有 commit 的 Git 仓库根目录。
- Moose 的目录锁约束 Moose 内的任务，不能锁住外部编辑器或 CLI；执行合并／清理时应避免外部进程同时修改同一目录。
- 本轮测试代理协议使用 fixture，不请求真实模型；Git 创建、合并、冲突和清理使用真实 Git 命令。

## Git 与原生审查

状态：已实现，纳入 0.10.0。0.9.0 安装包包含第二、三阶段，不包含本页新增功能。

### 最小成本复测

以下测试使用临时真实 Git 仓库、本地 bare remote、模拟 Codex／GitHub CLI；不调用真实模型，不创建远端 PR，不修改你的项目分支。

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm test:e2e --grep 'stages exact files|previews explicit PR'
```

更快的后端边界测试：

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm exec vitest run tests/unit/git-actions.test.ts tests/unit/review-workbench.test.ts
```

`PATH` 前缀解决终端能找到 pnpm、却找不到 node 的情况；Node 安装在其他位置时替换对应目录。

### 入口与行为

打开右侧“审阅改动”，所有操作使用当前会话的实际目录，包括受管 worktree。

- 每个文件可暂存或取消暂存；仅作用于对应文件（Git 识别出的重命名包含原路径）。暂存单位是文件，不提供逐 hunk 暂存。
- “提交预览”列出完整暂存文件清单及 diff。提交前核对分支、HEAD 和完整暂存区指纹；变动后需重新预览。失败保留提交说明，并在对话框显示错误。
- 保留 Git hooks 和签名配置。提交后核对实际树；如果 hook 或外部程序改变内容，明确报告已创建的 commit，要求检查，不伪造正常成功，也不自动撤销。
- 合并、rebase、cherry-pick 等未结束时阻止普通暂存／提交；受管合并继续使用 Worktree 面板的冲突处理。
- “拉取请求”要求安装并登录 `gh`，且 `origin` 为 github.com。输入目标分支，预览当前已推送分支到目标分支的提交与 diff；创建前再次核对仓库、HEAD 和远端目标。现有 OPEN PR 返回原链接，显示 OPEN／CLOSED／MERGED 状态。
- PR 预览会 fetch 选定 base，以本地 Git 对象生成 diff；不会检出分支或合并。当前不自动 push、不支持跨 fork、企业版 GitHub 或其他托管平台。创建的是草稿 PR。
- “原生代码审查”支持 Codex 0.155+，可选未提交改动、相对分支或指定提交。调用新 `thread/start` 后的 inline `review/start`，使用只读 sandbox／禁止权限提升；保留所选模型和推理强度，不恢复执行线程。
- 审查独立保存目标、native ID、正文、状态及错误；展示底座给出的文件路径和行号，可单独停止。窗口关闭后服务继续；退出／重启时未确认结果标为未知，不自动重新调用模型。

### 持久化与限制

提交和 PR 请求在执行前保存意图及 request ID。同一 ID 不重复执行；异常断开时保守记录结果未知。刷新 Git 或 PR 状态后再由用户选择下一步。审查结果保存在独立记录，不写入执行会话历史。

Moose 的目录锁约束自身代理、Git 操作与审查，不能锁住外部终端或其他客户端；预览后应避免同时从其他工具改动同一 checkout。截断 diff 明确提示，二进制改动由 Git 描述，完整文件清单仍保留。普通提交不用于完成冲突合并。

本轮原生审查验证基于仓库已核对的 Codex 0.155 协议类型与严格 fixture，覆盖独立只读线程、目标参数、结果事件、无关线程完成通知、停止与退出。为了省模型 token，没有调用真实模型做新审查，也没有用真实 GitHub 创建测试 PR。

### 本次验证记录

2026-09-19 发布前复核：86 项单元测试、完整 27 项 Electron 回归通过；路径处理最终调整后，7 项 Git 操作测试再次通过。类型检查、Lint、格式检查与 `git diff --check` 通过。构建仅保留已有的大 chunk 提示。

新增场景覆盖：子目录暂存与 diff.relative 完整预览、字面路径与未暂存内容隔离、无首个提交时取消暂存、重命名后继续编辑、陈旧 HEAD／index、hook 拒绝及修改提交树、冲突拒绝、worktree 目录归属、重复请求、PR 已发布 head／base 漂移／精确正文、独立只读审查、无关线程通知、停止／退出／重启、禁用底座和不支持的交互问题。

## 配置与扩展

状态：Codex 首批能力纳入 0.11.0，安装包验证见 [0.11.0 发布记录](0.11.0.md)。0.10.0 安装包不包含本页新增入口。

### 入口与范围

选择项目／会话后，点击顶部拼图图标“配置与扩展”。查询使用当前会话的实际工作目录，包含隔离 worktree。

- 配置来源：显示底座报告的用户、项目、系统等层及禁用状态；显示模型、推理强度、审批和 sandbox 的有效值与来源。只允许写入底座可写的用户配置层，不写项目配置、托管配置或 profile。
- 默认模型：输入后先预览目标配置文件与值，再应用；现有会话显式选择的模型仍优先生效。
- MCP：显示已配置服务器、认证状态、工具数量和发现失败标记；支持用户级启用／禁用、浏览器 OAuth、状态轮询和取消。新增 HTTP／STDIO 服务器支持预览与版本化写入，保存时保持禁用，之后单独启用。HTTP 支持环境变量名引用 Bearer token，STDIO 支持按数组传入参数和转发环境变量名；不提供密钥值编辑器。
- 插件：默认显示已安装项；搜索查询可用目录，最多显示 100 个匹配项。安装／卸载走 `codex plugin` CLI；启用／禁用走版本化配置写入。安装时需交互认证或受管理策略约束的项目，需在底座 CLI 操作。
- Hooks：仅显示事件、来源、启用状态、处理器类型；错误定位到来源文件。命令、环境变量、headers、凭据与原始底座错误均不透传给界面。
- Grok／Pi：明确显示尚无已验证管理接口，继续由各自 CLI 管理；不将 Codex 插件配置套用给其他底座。

用户级写入影响其他项目。保存前检查来源和版本；Moose 有活动任务／目录操作时拒绝配置写入，保存期间暂停启动队列。保存后启动新的读取连接，核对实际生效状态；若被更高优先级配置覆盖，会显示诊断。同一请求 ID 不重复执行；断连或重启后不自动重放未确认操作。

认证 URL 只通过内存传给系统浏览器，不进入聊天或数据库。认证最长等待约一分钟；取消关闭本次原生连接，不撤销已经由服务端颁发的凭据。退出应用会清理待定认证；重启后需重新发起。关闭弹窗本身不会取消认证，可重新打开查看。

### 新增 MCP 的使用范围

“新增 MCP 服务器”使用可写用户配置层；同名条目即使来自禁用的项目层也不覆盖，外部配置版本变化则拒绝保存。新增注册不会启动 STDIO 程序或建立新 HTTP 连接；需要另行点击“启用”。新增配置正文只供本次表单预览，重读结果不返回命令、参数、URL 或凭据引用；数据库操作回执仅保存请求指纹。

HTTP 只接受 HTTPS 或回环地址 HTTP，不支持 URL 内的用户名、密码、查询参数和片段；需要这些选项的服务器请继续使用 CLI 配置。STDIO 程序与参数分别填写，不把参数拼成 Shell 命令。环境变量名需已由底座进程继承，Moose 不创建或保存其密钥值。字段依据 [OpenAI 官方 MCP 文档](https://developers.openai.com/zh-Hans/docs/extend/mcp)。0.11.0 尚无编辑／删除既有 MCP 配置或自定义 headers 的入口；下述开发增量已补齐用户层连接编辑、移除及环境变量请求头。

## 终端与调度

### 后台命令

选中项目或会话后，点击顶部终端图标“后台命令与定时任务”。面板显示目标目录，命令使用会话的真实工作目录（包括受管 worktree）。

- 这些进程由 Moose 管理，不冒充 Codex／Grok 内部的终端，也不接管底座工具已创建的进程。
- 通过本机 `/bin/zsh` 执行脚本，使用当前本机用户权限。支持 stdout／stderr 文本、发送一行标准输入、关闭输入（EOF）、停止、退出码与信号。
- 0.11.0 的命令页是文本面板，不是 PTY：不支持 vim／top 等全屏程序、交互式 TTY 提示、终端尺寸变化。请勿用它启动自行脱离进程组的守护进程。
- 命令占用同一套实际目录锁；同目录的代理执行、Git 写入、原生历史变更与 worktree 操作不能并发写入，不同目录可并行。运行命令期间发送代理消息会提示等待；已经排队的消息在释放锁后继续。
- 关闭窗口继续运行；正常退出应用会停止命令组，状态保存为 `interrupted`。运行进程意外退出时，通过专用父进程管道的 EOF 清理命令进程组；重启后的旧运行记录为 `unknown`，不会重放，也不会根据磁盘上保存的旧 PID 杀进程。
- 命令文本和输出保存在 Moose 的本地数据库；输入本身不单独记录，但命令可能把输入回显到输出。每条输出最多保留最近约 128K 字符，每个项目保留最近 100 条命令的输出；较早的请求记录保留用于防止重试重复执行。

最小手动测试，无模型 token：运行 `read line; printf 'received:%s' "$line"`，在输入栏发送 `hello`，应看到 `received:hello` 和退出码 0；再运行 `sleep 30` 并点“停止命令”。

### 定时任务

在同一面板中填写名称、类型、正文、首次执行时间、重复间隔，预览后创建：

- 类型为 Shell 命令或代理消息。代理消息必须绑定现有会话，进入现有持久化队列，沿用该会话执行时的底座、模型和权限设置；以普通 Build 模式运行，不自动设为 Goal 或 Plan。可能消耗模型额度。
- 支持单次和固定经过时长的间隔；间隔 0 为单次，重复最少 1 分钟。界面用本机时区输入首次时间，保存绝对时间和时区标识，列表用所存时区显示。不是日历 cron，夏令时／时区变化不会把固定间隔变成每天固定钟点。
- 应用必须保持运行；只关闭窗口仍会触发。退出期间不执行。正常重启或休眠恢复后，尚未领取的错过周期最多合并补跑一次，后续时间前移到将来的周期。
- 同一定时任务上一轮处于排队或运行状态时不重复触发。忙碌目录等待释放，队列与不同 worktree 并行规则沿用现有服务。曾被用户停止、失败或重启暂停的代理会话，需先在会话中恢复队列；调度器不自行解除这种暂停。
- 领取周期和代理消息入队在同一个 SQLite 事务中完成；命令在持久化领取之后启动。崩溃窗口内结果不确定时，保存 `unknown` 并暂停定时任务，不假装成功、不自动重发。用户需核对现有结果后明确恢复；因此提供的是避免自动重复的语义，不保证崩溃期间每次都必达。
- 重启先核对已保存的命令结果：命令已经完成、但定时器尚未同步状态时，恢复为实际终态，不再误报未知。已持久化且仍在会话队列里的任务保留“排队中”，暂停后续触发；在原会话恢复或移除该消息，不另建重复消息。尚无可靠终态记录的代理运行仍按未知处理。
- 执行失败／取消会暂停后续触发。按钮“暂停后续触发”只改变未来调度，不停止已领取的命令或代理回合；停止命令在命令区操作，代理任务在原会话停止，未开始的消息可从会话队列移除。
- 单次任务触发后不能用“恢复”重新执行，需要新建。已领取的运行记录、最后状态、错误和下次触发时间可在面板查看；命令输出在命令区，代理回复在原会话。
- 删除已归档会话或项目会删除其关联调度与命令记录，不删除项目里的文件。

### 修改已有定时任务

先点“暂停后续触发”，再点“编辑定时任务”。支持修改名称、类型、正文、下次触发时间和间隔，预览后保存，保存后保持暂停；核对好后点“恢复定时任务”。取消编辑不写入，修改任一字段会撤销上一次预览。

- 预览显示将保存的内容、目标目录、绝对时间对应的时区和间隔。输入时间使用本机时区；已有任务保留原来的时区标识，预览与列表仍用该时区显示。不改时间时保留原始时间戳精度。
- 绑定的项目、会话和目录不会随编辑改变；不能借由编辑将无会话的命令改成代理消息。任务列表包含项目内其他会话时，编辑仍绑定原会话。
- 正在排队或运行的任务不能改，需等待结束或从原会话移除排队项。已触发的单次任务不能重新激活，需新建；周期任务可以改成未来再执行一次，已有执行记录保留。
- 保存检查读取时的版本；另一窗口或请求已改动该任务时会拒绝覆盖，保留输入供核对。取消并重新打开编辑可加载最新状态。
- 重试原始创建请求只返回已有任务，不会覆盖后续编辑、恢复暂停状态或再次触发。

最小手动验收，无模型 token：创建一个五分钟后的 Shell 任务 `printf before`，暂停并编辑为 `printf after`，预览后取消，列表应仍是 `before`；重新编辑并保存，列表应是 `after` 且仍暂停。无需等待实际触发。

### 交互终端增量（0.12.0）

面板新增“终端”页，与“最近命令”“定时任务”分开。点击“新建终端”在所选会话的实际目录打开 zsh。使用 node-pty 和按需加载的 xterm.js，支持 ANSI 颜色、光标控制、备用屏幕、交互式程序、Ctrl+C、粘贴和尺寸同步。终端内的 Escape 交给程序处理，不关闭外层窗口。

终端独占实际目录，直到退出或点击“关闭终端”，避免与代理或调度任务同时修改文件。收起面板和关闭应用窗口不结束终端；退出应用会停止它。不会接管底座原生工具进程，也不会把终端文本发送给模型。

独立的 `pty-host` 进程负责 Shell。运行进程通信管道关闭时，宿主清理仍属于该 Shell 的普通子进程。强制杀死运行进程后，重启将原来的运行状态标成 unknown，不恢复旧 PID，也不自动重放输入。自行守护化、脱离父子关系的进程不在回收保证范围内。

每个终端保留最多 1,048,576 个 UTF-16 码元的输出尾部，使用绝对偏移读取增量；每项目保留最近 30 个会话的完整尾部。较老内容会截断，界面明确提示。回放时不会把终端协议应答重新写回 Shell。未安装自动打开链接或读写系统剪贴板的终端输出扩展。当前版本面向 macOS，使用 `/bin/zsh`；未宣称 Windows 支持。
