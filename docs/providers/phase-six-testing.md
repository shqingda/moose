# 第六阶段：后台命令与定时任务验收

状态：首批能力纳入 0.11.0，安装包验证见 [0.11.0 发布记录](../releases/0.11.0.md)。0.10.0 安装包不包含本页新增能力。

## 后台命令

选中项目或会话后，点击顶部终端图标“后台命令与定时任务”。面板显示目标目录，命令使用会话的真实工作目录（包括受管 worktree）。

- 这些进程由 Moose 管理，不冒充 Codex／Grok 内部的终端，也不接管底座工具已创建的进程。
- 通过本机 `/bin/zsh` 执行脚本，使用当前本机用户权限。支持 stdout／stderr 文本、发送一行标准输入、关闭输入（EOF）、停止、退出码与信号。
- 0.11.0 的命令页是文本面板，不是 PTY：不支持 vim／top 等全屏程序、交互式 TTY 提示、终端尺寸变化。请勿用它启动自行脱离进程组的守护进程。
- 命令占用同一套实际目录锁；同目录的代理执行、Git 写入、原生历史变更与 worktree 操作不能并发写入，不同目录可并行。运行命令期间发送代理消息会提示等待；已经排队的消息在释放锁后继续。
- 关闭窗口继续运行；正常退出应用会停止命令组，状态保存为 `interrupted`。运行进程意外退出时，通过专用父进程管道的 EOF 清理命令进程组；重启后的旧运行记录为 `unknown`，不会重放，也不会根据磁盘上保存的旧 PID 杀进程。
- 命令文本和输出保存在 Moose 的本地数据库；输入本身不单独记录，但命令可能把输入回显到输出。每条输出最多保留最近约 128K 字符，每个项目保留最近 100 条命令的输出；较早的请求记录保留用于防止重试重复执行。

最小手动测试，无模型 token：运行 `read line; printf 'received:%s' "$line"`，在输入栏发送 `hello`，应看到 `received:hello` 和退出码 0；再运行 `sleep 30` 并点“停止命令”。

## 定时任务

在同一面板中填写名称、类型、正文、首次执行时间、重复间隔，预览后创建：

- 类型为 Shell 命令或代理消息。代理消息必须绑定现有会话，进入现有持久化队列，沿用该会话执行时的底座、模型和权限设置；以普通 Build 模式运行，不自动设为 Goal 或 Plan。可能消耗模型额度。
- 支持单次和固定经过时长的间隔；间隔 0 为单次，重复最少 1 分钟。界面用本机时区输入首次时间，保存绝对时间和时区标识，列表用所存时区显示。不是日历 cron，夏令时／时区变化不会把固定间隔变成每天固定钟点。
- 应用必须保持运行；只关闭窗口仍会触发。退出期间不执行。正常重启或休眠恢复后，尚未领取的错过周期最多合并补跑一次，后续时间前移到将来的周期。
- 同一定时任务上一轮处于排队或运行状态时不重复触发。忙碌目录等待释放，队列与不同 worktree 并行规则沿用现有服务。曾被用户停止、失败或重启暂停的代理会话，需先在会话中恢复队列；调度器不自行解除这种暂停。
- 领取周期和代理消息入队在同一个 SQLite 事务中完成；命令在持久化领取之后启动。崩溃窗口内结果不确定时，保存 `unknown` 并暂停定时任务，不假装成功、不自动重发。用户需核对现有结果后明确恢复；因此提供的是避免自动重复的语义，不保证崩溃期间每次都必达。
- 重启先核对已保存的命令结果：命令已经完成、但定时器尚未同步状态时，恢复为实际终态，不再误报未知。已持久化且仍在会话队列里的任务保留“排队中”，暂停后续触发；在原会话恢复或移除该消息，不另建重复消息。尚无可靠终态记录的代理运行仍按未知处理。
- 执行失败／取消会暂停后续触发。按钮“暂停后续触发”只改变未来调度，不停止已领取的命令或代理回合；停止命令在命令区操作，代理任务在原会话停止，未开始的消息可从会话队列移除。
- 单次任务触发后不能用“恢复”重新执行，需要新建。已领取的运行记录、最后状态、错误和下次触发时间可在面板查看；命令输出在命令区，代理回复在原会话。
- 删除已归档会话或项目会删除其关联调度与命令记录，不删除项目里的文件。

## 修改已有定时任务

先点“暂停后续触发”，再点“编辑定时任务”。支持修改名称、类型、正文、下次触发时间和间隔，预览后保存，保存后保持暂停；核对好后点“恢复定时任务”。取消编辑不写入，修改任一字段会撤销上一次预览。

- 预览显示将保存的内容、目标目录、绝对时间对应的时区和间隔。输入时间使用本机时区；已有任务保留原来的时区标识，预览与列表仍用该时区显示。不改时间时保留原始时间戳精度。
- 绑定的项目、会话和目录不会随编辑改变；不能借由编辑将无会话的命令改成代理消息。任务列表包含项目内其他会话时，编辑仍绑定原会话。
- 正在排队或运行的任务不能改，需等待结束或从原会话移除排队项。已触发的单次任务不能重新激活，需新建；周期任务可以改成未来再执行一次，已有执行记录保留。
- 保存检查读取时的版本；另一窗口或请求已改动该任务时会拒绝覆盖，保留输入供核对。取消并重新打开编辑可加载最新状态。
- 重试原始创建请求只返回已有任务，不会覆盖后续编辑、恢复暂停状态或再次触发。

最小手动验收，无模型 token：创建一个五分钟后的 Shell 任务 `printf before`，暂停并编辑为 `printf after`，预览后取消，列表应仍是 `before`；重新编辑并保存，列表应是 `after` 且仍暂停。无需等待实际触发。

## 零模型 token 自动验收

```sh
export PATH="/opt/homebrew/bin:$PATH"
pnpm exec vitest run tests/unit/background.test.ts tests/unit/service.test.ts
pnpm test:e2e --grep 'background commands|one-time command|edits paused schedules'
```

测试使用临时目录、真实本地 shell 和代理夹具：

- 标准输入／EOF、失败退出、输出截断、同目录互斥与不同目录并行。
- 重复请求不再运行，进程组停止和正常退出状态。
- 强制杀死独立测试运行进程，验证其拥有的命令退出。
- 模拟时钟跨过多个周期，只合并一次；未完成期间不重叠。
- 单次不重复、版本冲突、忙碌等待、事务回滚、失败暂停及重启未知状态。
- 暂停编辑、旧请求重试、绑定目录校验、运行中拒绝修改；周期任务改成单次且不能再次激活。
- 重启读取命令完成记录，保留真实队列项且不重复入队。
- 代理定时任务走现有队列并记录完成，不调用真实模型。
- Electron 的命令输入与停止、定时任务预览和暂停；窗口关闭后真实触发命令，重开窗口及重启应用后不重复写入。
- Electron 的编辑预览、取消、保存后仍暂停、字段变更撤销预览、跨时区时间保留及并发版本冲突。

系统休眠通过时钟跳跃模拟，本轮未让整机实际休眠；未对自行脱离进程组的守护程序提供生命周期保证。该发行批次不含交互式 PTY；下述开发增量已补齐。每天／每周日历调度见下述开发增量；任意 cron、系统级唤醒／应用退出后执行、底座原生命令接管仍未实现。

## 交互终端增量（0.12.0）

面板新增“终端”页，与“最近命令”“定时任务”分开。点击“新建终端”在所选会话的实际目录打开 zsh。使用 node-pty 和按需加载的 xterm.js，支持 ANSI 颜色、光标控制、备用屏幕、交互式程序、Ctrl+C、粘贴和尺寸同步。终端内的 Escape 交给程序处理，不关闭外层窗口。

终端独占实际目录，直到退出或点击“关闭终端”，避免与代理或调度任务同时修改文件。收起面板和关闭应用窗口不结束终端；退出应用会停止它。不会接管底座原生工具进程，也不会把终端文本发送给模型。

独立的 `pty-host` 进程负责 Shell。运行进程通信管道关闭时，宿主清理仍属于该 Shell 的普通子进程。强制杀死运行进程后，重启将原来的运行状态标成 unknown，不恢复旧 PID，也不自动重放输入。自行守护化、脱离父子关系的进程不在回收保证范围内。

每个终端保留最多 1,048,576 个 UTF-16 码元的输出尾部，使用绝对偏移读取增量；每项目保留最近 30 个会话的完整尾部。较老内容会截断，界面明确提示。回放时不会把终端协议应答重新写回 Shell。未安装自动打开链接或读写系统剪贴板的终端输出扩展。当前版本面向 macOS，使用 `/bin/zsh`；未宣称 Windows 支持。

实际桌面测试覆盖：TTY 检测、`stty size`、vim 编辑并保存文件、Ctrl+C、收起与重开、目录锁释放、运行进程 SIGKILL 后回收 Shell 和子进程、重启 unknown、输出截断、正常退出后的 interrupted 状态及重复请求不创建新终端。所有这些测试运行真实本机进程，使用临时项目和数据库，不调用模型。

新增原生依赖后，已重新构建 Apple Silicon `.app`，严格签名校验通过，安装包内 PTY 也通过 TTY 检测和输入输出验收。此项开发验证后纳入 0.12.0。

验证结果：完整桌面回归 37 项通过；单测共 128 项，新增校验测试修正 UUID 测试数据后定向复测通过，其余 126 项完整回归通过。类型检查、lint、格式检查、diff 检查及打包后的 PTY 验收通过。

## 后续开发增量：日历调度（0.12.0）

- 新建和编辑时直接选择单次、固定间隔、每天或每周指定日。日历任务可选执行时间和 IANA 时区，不需要写 cron。
- 确认前显示接下来三次执行时间；修改任意字段后需重新预览。保存使用预览中的时间，不会在确认时悄悄换成新时间。
- 夏令时跳过不存在的本地时间；重复钟点仅采用第一次。支持半小时／四十五分钟等非整小时偏移。
- 暂停后恢复从下一个符合规则的时间继续，不补暂停期间的任务。应用运行中漏过多个时间点时合并为一次，前一次未结束时不会重叠。
- 保留原有一次性／固定间隔记录和创建请求去重；编辑为其他频率会清除旧日历规则。
- 仍需 Moose 进程运行；不包含应用退出后的系统服务、月度规则或任意 cron。

低成本验收：打开后台面板 → 定时任务 → 新建，选择每周指定日，填写时间和时区，点击预览查看下三次时间。创建后可暂停、编辑并重新预览。只检查表单与预览不会调用模型；若保存代理消息任务，到点执行才会产生模型消耗。也可选择命令并填写 `printf calendar-check` 验证执行。

自动验证覆盖跨年、夏令时跳过／重复、非整小时时区、漏跑合并、暂停恢复、编辑兼容与桌面创建编辑流程；均使用固定时钟或测试底座，无真实模型调用。

本批验证：134 项单测、38 项桌面回归全部通过；预览自动定位调整后，日历创建／编辑流程再次通过。构建、类型检查、lint、格式与 diff 检查通过。纳入 0.12.0。

## 0.12.0 后界面增量（0.13.0）

终端顶部的位置选择可切换“弹窗／底部／右侧”。底部和右侧模式下可以继续编辑对话；关闭面板只隐藏界面，方形停止按钮才结束当前终端。位置切换保留当前进程与输出。打开 Git 审阅时，右侧终端自动移到底部。终端输出填满剩余内容区，原有说明文案收起。

验收可在终端输入 `export MOOSE_LAYOUT_CHECK=ok`，切换三个位置后输入 `echo "$MOOSE_LAYOUT_CHECK"`，应仍输出 `ok`。此操作不调用模型。

## 终端标签修正（0.13.0 后）

同一目录可打开多个交互终端。每个标签显示“用户名@主机名”，右侧 × 结束该 Shell 并移除标签；面板顶部的关闭按钮只隐藏面板。关闭后的终端不出现在列表，重启也不会恢复。内部执行回执仍用于重复请求去重，不提供终端历史回顾入口。

最小验收：打开终端面板，连续点两次 +；分别输入 `echo one` 和 `echo two`，切换标签确认独立输出，再关闭一个，另一个应继续可用。两个终端全关后，后台命令应能正常运行。全过程不调用模型。

自动回归增加同目录双 PTY、键盘切换标签、关闭后不再列出，以及最后一个终端关闭才释放目录锁的验证。

## 手动命令与终端并行

修正：手动 Shell 命令也加入终端使用的共享目录锁。终端开着时可在“命令”页运行测试；反过来，命令执行中也可打开终端。所有手动命令和终端都结束后才允许其他目录操作。定时任务依然等目录空闲后再执行。

自动验收在临时项目创建最小 package.json，实际执行 `pnpm test`，检查成功输出；同时验证关闭终端后，仍在运行的命令继续阻止删除项目，最后停止命令后目录才解除占用。还验证 Latte／Mocha 随深浅模式切换。此处没有向模型发送消息。
