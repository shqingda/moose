# 第三阶段验收：Worktree 与并行工作

已纳入 0.9.0 及后续安装包。入口是项目右上角的“独立工作目录”。

## 最低成本验收

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm test:e2e --grep 'isolates agent writes|two isolated conversations'
```

使用真实 Electron、真实临时 Git 仓库和模拟代理，**不消耗模型 token**。覆盖隔离写入、会话目录中的 diff、合并预览与提交、保留与清理，以及同项目两个会话同时运行。

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm exec vitest run tests/unit/worktrees.test.ts
```

额外覆盖同目录串行、引用搜索范围、未跟踪／忽略文件保护、未合并提交保护、活动／排队任务保护、过期合并预览、冲突跨重启恢复、解决并暂存、中止合并、符号链接替换、重复创建和创建失败恢复。

## 使用流程

1. 添加 Git 仓库根目录为项目。打开“独立工作目录”，输入起始 ref（默认 `HEAD`，也可用分支、tag、commit）和新的分支名，点击“创建隔离会话”。创建新的空会话和受管 Git worktree，不改变原会话的 native ID 或目录。
2. 在两个不同工作目录的会话分别发送任务，两者可同时执行。同一目录中的会话仍串行；底座自行创建的子代理仍由底座管理。
3. 当前会话的文件引用、项目 skills、执行、编辑器／Finder、Git diff、原生历史与显式原生分叉均跟随会话目录。项目根目录仅用于项目归属和默认合并目标。
4. 完成修改后在相应工作目录提交代码。通用暂存／提交界面属于第四阶段，本阶段只提供合并专用的冲突暂存及合并提交。
5. 回到“独立工作目录”，刷新状态，检查目标路径、目标分支、两端 commit 和 diff，再点击“准备合并到项目”。目标固定为项目根目录当前检出的分支；本阶段不提供任意目标分支选择器。
6. 干净合并也不会立即提交。检查暂存后的 diff，点击“提交已审阅的合并”。如有冲突，点击“在编辑器中打开合并目标”，编辑冲突文件，逐一点击“已解决并暂存”，然后完成合并；也可显式中止。
7. 工作目录保持在磁盘上，不自动删除。“保留工作目录”会进一步禁用清理按钮。允许清理后，只有空闲、无排队任务、无未提交／未跟踪／忽略文件、无未合并到当前项目分支的提交时才允许清理。清理保留分支和聊天记录，不把旧会话悄悄切回项目根目录。

## 恢复与限制

- 受管目录位于 Moose 数据目录的 `worktrees/<projectId>/<worktreeId>` 下；数据库 schema 5 保存工作目录记录和会话关联。会话删除后目录仍受项目管理；项目删除前需要清理受管目录。
- 创建和清理先记录意图再调用 Git。打开状态面板时核对磁盘与 Git 注册，应用重启不自动再次创建、删除或合并；失败记录可检查和清理。
- 合并期间两个相关目录停止接收新任务，其他 worktree 可以继续运行。冲突与合并状态落库；重启后可检查并继续或中止。
- 来源、目标 commit／分支或暂存内容改变后，过期预览不能直接继续提交。异常的外部 Git 状态会拒绝操作并保留现场。
- 未提交的项目修改、依赖、忽略文件及聊天历史不会复制到新目录。需要在新目录自行准备依赖；例如 `node_modules` 会阻止清理，避免自动删除用户未检查的文件。
- 不支持把已有会话原地搬到另一目录、自动拷贝脏文件、任意目标 worktree 合并或自动删除分支。项目必须是已经有 commit 的 Git 仓库根目录。
- Moose 的目录锁约束 Moose 内的任务，不能锁住外部编辑器或 CLI；执行合并／清理时应避免外部进程同时修改同一目录。
- 本轮测试代理协议使用 fixture，不请求真实模型；Git 创建、合并、冲突和清理使用真实 Git 命令。
