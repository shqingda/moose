# 第二阶段验收：原生会话与子代理面板

已纳入 0.9.0 及后续安装包。入口是项目右上角的“原生会话”，子代理活动中的“打开子代理”打开独立面板。

## 最低成本验收

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm test:e2e --grep 'imports paginated|replays Grok|opens child history'
```

这三条测试启动真实 Electron、临时数据库和模拟 CLI，不连接真实模型、不消耗模型 token：

- 原生列表和正文分页、重复导入、重载后关联不丢、按回合分叉及来源记录、等待压缩完成事件。
- Grok 历史回放导入；分叉和压缩按钮不可用。
- 子代理历史独立展示、发送与停止只针对子线程、未知线程拒绝、审批继续归属于父会话。

服务与协议单测另外覆盖跨项目拒绝、分页失败不产生半份导入、循环游标、操作幂等、断连结果未知、请求 ID 冲突、重启不重放、旧协议版本、子线程完成不完成主任务。

## 自己点一遍

1. 在当前项目点“原生会话”，预览一条已有 Codex／Grok 历史，再点“导入或打开会话”。第二次导入应打开同一条 Moose 会话。
2. 在空闲的 Codex 会话打开同一面板，选择用户回合，点“从所选回合分叉”。新会话显示来源 ID 和分叉点；原会话不变。**这不会隔离或回滚项目文件**。
3. 在已有子代理活动中点“打开子代理”，查看父线程、原生状态、模型和历史。父任务仍活动且底座允许直接输入时才可发送；停止只中断子线程的活动回合。底座接收请求不代表子任务已经完成。
4. “压缩原生上下文”会请求底座压缩，可能消耗模型 token；为了省额度，可以跳过手动压缩，用上述模拟测试验收状态流程。真正压缩完成前项目保持互斥，关闭面板不会停止压缩。

导入和分叉的历史记录是导入时的快照；以后用外部 CLI 写入的内容不会自动同步到 Moose 时间线。可从原生历史面板重新读取最新内容，重复导入不会覆盖已有本地记录。原始附件只保留类型占位；不复制底座私有附件文件。

## 原生接口核验记录

2026-09-19，在本机用以下命令验证，只输出计数和能力，不输出对话正文，也不发送 prompt：

```sh
PATH="/opt/homebrew/bin:$PATH" pnpm exec tsx scripts/check-native-sessions.ts
```

| 底座 | 本次真实验证 | 边界 |
| --- | --- | --- |
| Codex 0.155.1 | 握手版本、`thread/list`、`thread/read`、`thread/items/list`，正文首批 40 项并返回后续游标 | 分叉、压缩与子代理控制的变更流程通过协议 fixture 验证；本轮没有消耗模型额度做真实压缩或新增委派 |
| Grok 1.0.34 | 握手声明 list/load；`session/list`、`session/load` 回放 | 不提供原生分叉、压缩或结构化子代理控制；ACP 分块按相邻角色合并，不宣称精确回合 ID |
| Pi | 无对应 adapter 能力 | 显示不支持 |

Codex 入口要求握手版本符合已核验的 0.155+ 协议。版本门槛不是所有未来版本的兼容保证；实际接口拒绝会直接显示错误。Grok 按握手 capability 开放历史入口。

Codex `thread/resume` 只是加载会话，不等同于恢复关闭的子任务，因此恢复按钮禁用并解释原因，请让主代理使用原生恢复工具。子代理控制依赖父任务所属的活动连接，便于将审批准确路由回父会话。父任务结束后历史仍可读，控制不再开放。

## 故障和持久化

- 导入按真实目录校验，全部页面读取成功后一次落库，拒绝把别的项目历史绑定到当前项目。
- 分叉／压缩／子代理控制先持久化请求 ID；底座拒绝和连接断开分别记录。未知结果和应用重启都不会自动重发。
- 分叉返回 native ID 后先保存记录，再导入正文；若正文读取失败，可用记录中的 ID 从原生历史重新导入。
- 压缩等待 `contextCompaction` 和对应 `turn/completed`；回执、其他线程完成或中断都不算成功。活动 Goal 需先暂停，防止加载时继续执行目标。
- 数据库升级到 schema 4 保存来源；旧版应用会拒绝读取新版数据库。安装包发布时应保留升级前备份。
- 操作互斥只覆盖 Moose 自己的项目任务；同时在外部 CLI 修改同一会话不受 Moose 锁控制。
