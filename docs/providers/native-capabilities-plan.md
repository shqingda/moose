## 后续优先级

先巩固现有流程，不为增加功能数量继续扩展面板或抽象层。

1. **长期运行与异常恢复。** 按实际问题补充共享后台、长会话、休眠、断连和版本升级的验证。重点检查状态是否明确、输入是否丢失、未知结果是否被误重发；先测量，再决定是否需要完整事件游标、专表或新的清理策略。
2. **更多底座原生能力。** Pi／OpenCode 历史与 Pi 插话已纳入 0.22.0。Grok 1.0.46 的规划模式切换未通过协议验证，继续保持不可用，等待上游提供可验证的流程。分叉／压缩扩展、更多配置能力按真实需求推进；先验证本机协议和最小流程，再开放入口。
3. **必要的辅助工具。** 文件只读预览与完成／待处理通知已交付；输出片段／笔记、会话置顶和导出备份仍保留为候选。现有只读文件树已经交付；后续按具体需求评估，不继续堆叠任务板与监控栏。

上述是工作顺序，不是已开始实施或承诺交付日期。新增任务应写清验收场景，再更新对应主文档。

## 已知限制与暂缓事项

| 范围 | 当前限制与决定 |
| --- | --- |
| 原生能力 | 各底座范围不一致；加载子线程不等于恢复关闭任务；部分真实模型链路仍仅有夹具证据 |
| Git | 无按代码块暂存、自动推送、跨 fork PR 或其他托管平台 PR；合并目标为项目根目录当前分支 |
| 配置 | 不写项目级配置、不编辑 Hooks；插件安装中的交互认证未接入；其他底座已有用户配置管理首批适配，具体范围见能力表 |
| 调度与后台 | 无月度／任意 cron、系统唤醒和开机自启；不恢复崩溃前的活进程；当前桌面菜单没有停止后台入口，使用命令行停止 |
| Web | 本机单用户为主；移动端适配、云端部署和正式远程登录暂缓 |
| 分发 | Apple Silicon macOS 桌面与 Web 包；Web 支持手动更新，自动安装升级、Developer ID 公证和其他平台仍待后续需求明确 |

暂缓不等于需要立即补齐。尤其不为当前本机使用引入多租户、微服务、通用工作流引擎或另一套代理运行时。

## 继续开发时遵循的约束

- 以实际工作目录协调并发；Moose 的锁不能阻止外部程序修改文件，提交等操作仍需重新校验状态。
- 先保存用户意图，再执行副作用；区分明确失败与结果未知，重启或重连不盲目重放写请求。
- 桌面和 Web 共用业务服务与数据库所有者，宿主能力与传输分别处理。
- 按职责提取模块，不按文件长度机械拆分；先删除重复逻辑，再考虑新抽象。
- 测试保留关键失败路径，日常定向验证，发布完成打包验收；默认后台运行。

当前验证方法见[测试指南](../testing.md)，架构边界见[技术架构](../architecture.md)。
