# 第五阶段：配置与扩展管理验收

状态：Codex 首批能力纳入 0.11.0，安装包验证见 [0.11.0 发布记录](../releases/0.11.0.md)。0.10.0 安装包不包含本页新增入口。

## 入口与范围

选择项目／会话后，点击顶部拼图图标“配置与扩展”。查询使用当前会话的实际工作目录，包含隔离 worktree。

- 配置来源：显示底座报告的用户、项目、系统等层及禁用状态；显示模型、推理强度、审批和 sandbox 的有效值与来源。只允许写入底座可写的用户配置层，不写项目配置、托管配置或 profile。
- 默认模型：输入后先预览目标配置文件与值，再应用；现有会话显式选择的模型仍优先生效。
- MCP：显示已配置服务器、认证状态、工具数量和发现失败标记；支持用户级启用／禁用、浏览器 OAuth、状态轮询和取消。新增 HTTP／STDIO 服务器支持预览与版本化写入，保存时保持禁用，之后单独启用。HTTP 支持环境变量名引用 Bearer token，STDIO 支持按数组传入参数和转发环境变量名；不提供密钥值编辑器。
- 插件：默认显示已安装项；搜索查询可用目录，最多显示 100 个匹配项。安装／卸载走 `codex plugin` CLI；启用／禁用走版本化配置写入。安装时需交互认证或受管理策略约束的项目，需在底座 CLI 操作。
- Hooks：仅显示事件、来源、启用状态、处理器类型；错误定位到来源文件。命令、环境变量、headers、凭据与原始底座错误均不透传给界面。
- Grok／Pi：明确显示尚无已验证管理接口，继续由各自 CLI 管理；不将 Codex 插件配置套用给其他底座。

用户级写入影响其他项目。保存前检查来源和版本；Moose 有活动任务／目录操作时拒绝配置写入，保存期间暂停启动队列。保存后启动新的读取连接，核对实际生效状态；若被更高优先级配置覆盖，会显示诊断。同一请求 ID 不重复执行；断连或重启后不自动重放未确认操作。

认证 URL 只通过内存传给系统浏览器，不进入聊天或数据库。认证最长等待约一分钟；取消关闭本次原生连接，不撤销已经由服务端颁发的凭据。退出应用会清理待定认证；重启后需重新发起。关闭弹窗本身不会取消认证，可重新打开查看。

## 新增 MCP 的使用范围

“新增 MCP 服务器”使用可写用户配置层；同名条目即使来自禁用的项目层也不覆盖，外部配置版本变化则拒绝保存。新增注册不会启动 STDIO 程序或建立新 HTTP 连接；需要另行点击“启用”。新增配置正文只供本次表单预览，重读结果不返回命令、参数、URL 或凭据引用；数据库操作回执仅保存请求指纹。

HTTP 只接受 HTTPS 或回环地址 HTTP，不支持 URL 内的用户名、密码、查询参数和片段；需要这些选项的服务器请继续使用 CLI 配置。STDIO 程序与参数分别填写，不把参数拼成 Shell 命令。环境变量名需已由底座进程继承，Moose 不创建或保存其密钥值。字段依据 [OpenAI 官方 MCP 文档](https://developers.openai.com/zh-Hans/docs/extend/mcp)。0.11.0 尚无编辑／删除既有 MCP 配置或自定义 headers 的入口；下述开发增量已补齐用户层连接编辑、移除及环境变量请求头。

## 最低成本自动验收

这些测试只调用临时协议／CLI 夹具，不调用模型，不安装真实插件，不写用户真实配置：

```sh
export PATH="/opt/homebrew/bin:$PATH"
pnpm exec vitest run tests/unit/extensions.test.ts
pnpm test:e2e --grep 'scoped configuration|cancels native authentication|MCP registration'
```

覆盖配置来源与敏感值过滤、用户配置写入及版本冲突、拒绝项目作用域、幂等重试、插件 CLI 安装与卸载、MCP／插件开关、OAuth 正常／失败／取消／提前完成／不安全 URL、并发认证与写入、退出清理、未知结果恢复，以及 Electron 预览应用流程。界面测试也检查长内容下标题和关闭按钮保持可见。

真实底座只读探测（不调用模型）：

```sh
export PATH="/opt/homebrew/bin:$PATH"
pnpm exec tsx scripts/check-extensions.ts
```

该脚本只输出数量、配置层类别和诊断类别，不打印配置正文、命令或认证信息。底座可能连接现有 MCP 服务器并读取本地插件目录。

2026-09-19 实测 Codex Desktop 0.155.1：2 个配置来源、4 个有效设置、5 个 MCP 服务器、4,192 个插件条目、0 个 hooks，无诊断错误；目录数量会随底座更新改变。真实配置写入、真实插件安装／卸载和真实服务端 OAuth 本轮未操作，写入链路由隔离夹具验证。

## MCP 管理与界面增量（0.12.0）

支持编辑用户层已有 HTTP／STDIO 连接、移除用户层条目。编辑保留启用状态、已存密钥和未涉及的高级选项；凭据变量留空沿用原值。连接地址、程序和参数需重新填写，不把原配置里可能含密钥的正文返回界面。改变传输方式需移除后重新添加。

新增 HTTP 请求头以环境变量引用填写，进入 Codex 的 `env_http_headers`。编辑按名称更新并保留其他请求头，名称大小写不造成重复。与已有明文请求头同名时拒绝写入，继续由 CLI 修改；本入口不提供明文密钥编辑和已有请求头删除。

移除通过 `config/value/write` 的 `replace` 策略更新用户层 MCP 表，保留其他服务器，并携带 `expectedVersion`。不删除继承来源的条目。移除后若其他来源的同名配置生效，界面保留该服务器并显示诊断；不能把移除用户条目误称为彻底禁用。

扩展页按 MCP、插件、代理、诊断分区；配置来源默认收起。确认窗口展示可读字段，保存后关闭新增或编辑表单。后台命令和定时任务也改为分区，新建任务表单按需展开。

真实 Codex 临时 `CODEX_HOME` 探测已验证整个 MCP 表的 replace 删除行为及 `env_http_headers` 写入。没有修改真实用户配置、连接真实 MCP 服务或调用模型。自动化覆盖编辑保留密钥、移除不影响其他服务器、版本冲突、继承来源拒绝、传输切换拒绝、请求头校验、确认取消及键盘分区导航。
