# 测试与验证

## 怎么选择测试

“回归”是测试目的，不是单元测试、E2E 之外的第三套测试。日常修改先运行相关用例；发布或修改共享基础设施时，再跑完整验证。

```sh
pnpm test                  # 单元测试：协议、状态转换、持久化和安全边界
pnpm test:e2e              # 构建后运行桌面与 Web 的端到端流程
pnpm test:providers        # 本机 CLI 握手和能力探测，不发送模型任务
pnpm test:live             # 真实模型流程，会消耗额度
pnpm exec tsx scripts/package-smoke.ts # 打包应用：版本、沙箱、SQLite、终端等
pnpm perf:measure          # 已打包应用的空工作区热启动测量
```

定向 E2E 可在 `pnpm build` 后运行 `pnpm exec playwright test --grep '用例名称'`。涉及原生模块时，遵循[开发与打包](development.md)的重建流程。

## 保留什么，删除什么

- 单元测试保留协议完成信号、取消、审批、插话投递状态、目录互斥、重启恢复和网络来源校验。这些失败路径不能靠一个界面成功用例替代。
- E2E 验证跨层用户流程，包括真实本地 Shell、桌面与浏览器共享任务、刷新后恢复审批，以及终端重新连接。
- 删除重复验证同一界面状态的用例；把独立的有效断言合并到相应流程。避免用精确像素间距锁死正常设计调整，但保留曾经反复出错的对齐、焦点和键盘行为。
- 安装包验收单独保留：源码运行正常，不能证明打包后的原生依赖和沙箱正常。

0.15.1 清理将 E2E 从 48 项合并为 46 项，保留 150 项单元测试。单元测试全量约 12 秒，没有为了缩小数量删除低成本的失败路径覆盖。移除了未被命令引用、与现有 E2E 重复的旧手工 UI 脚本。

## 验证边界

自动化主要使用隔离数据库、测试 CLI 和真实本地 Shell，不调用真实模型。协议夹具通过不等于模型能力已实测；真实 CLI 探测与真实模型验收分别记录，不混写。

性能脚本使用临时数据、禁用代理发现，以同一个空工作区连续启动三次。它测量温缓存下欢迎界面可见的耗时、进程工作集之和与 renderer JS 堆，不是冷启动或长会话压力测试。解释与本轮结果见[面试指南](interview/project-interview-guide.md)。

历史发布的验证证据保留在各版[发布记录](releases/0.15.0.md)，本页只维护当前方法。Web 启动与限制见 [Web 使用说明](web.md)，底座支持范围见[原生能力](providers/native-capabilities.md)。
