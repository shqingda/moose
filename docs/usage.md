# 使用指南

## 安装与连接

从 [GitHub Releases](https://github.com/shqingda/moose/releases/latest) 下载 arm64 DMG，将 Moose.app 放到 Applications。

安装包采用 ad-hoc 签名，打包时严格验证完整性，但尚未进行 Apple Developer ID 签名及公证。首次下载可能被 Gatekeeper 拦截，在“系统设置 → 隐私与安全性”中允许打开。签名完整性与下载隔离是两回事，Moose 不会自动移除系统下载隔离标记。

先在终端安装并登录代理，再到设置 → 服务商刷新检测。找不到 CLI 时填写绝对路径，点击输入框外自动保存并重新检测；开关可停用已检测到的代理。自动发现读取登录交互 shell 的 PATH，并缓存 30 秒；同时补充 pnpm、Bun、Volta、Homebrew 等常见安装目录。自定义位置只要已加入 shell 的 PATH，通常无需在应用中填写。shell 读取失败时回退，shell alias / function 不作为可执行文件发现。

| 代理 | 登录及说明 |
| --- | --- |
| Codex | 使用系统 CLI（支持 Homebrew 路径），执行 `codex login`；不在项目内安装 |
| Grok Build | 通过官方 CLI 登录 Grok / SuperGrok 账号 |
| Pi | 安装并运行 `pi`，使用 `/login`；详见 [Pi 接入](providers/pi.md) |

模型和推理档位来自实际 CLI 能力。已有会话固定代理，换代理需新建会话。

## 后台和浏览器

安装版打开后自动连接或启动本机后台，原来的项目、会话和附件保留在原目录。菜单 **Moose → 在浏览器中打开** 可以访问同一个工作区。

普通退出会保留后台任务和终端；需要结束全部任务时，选择 **退出并停止后台**。升级时如果提示后台版本不同，先用该菜单停止旧后台，再重新打开 Moose。后台不会随电脑开机自动启动，电脑重启也不会恢复原来的活进程。更多说明见 [Web 使用说明](web.md)。

## 项目和会话

打开项目目录后发送消息，首条消息发送后会话才出现在侧栏。点击项目行折叠或展开会话，不切换当前对话。

项目可从 Moose 删除，需确认，不删除代码目录或官方 CLI 历史。会话先归档，在归档列表中恢复或删除。归档当前会话后回到未保存的新输入页。

只能编辑最近一条用户消息的文字，附件保持不变；发送后在原会话替换该轮。较早的消息仅可复制。AI 一轮回复的多段正文合并复制。编辑不回滚代码文件，也不提供独立的“回到这条消息”入口。

同一个规范化目录一次运行一个 Moose 任务，不同目录可并行；这不限制外部 CLI 或编辑器。运行期间按 Enter 或普通发送按钮，后续输入进入可编辑、可取消的队列。Codex 另有“立即发送”按钮，将输入追加到当前回合；不能通过插话改变任务模式或权限。若投递结果未知，先核对代理回复，不要直接重复发送。停止或重启后队列保持暂停，需主动恢复。

## 输入、权限与审阅

- `@` 模糊搜索项目文件和目录；`/` 选择当前代理支持的任务模式和 skills。引用是可编辑文本，删除引用文本会移除对应上下文。
- 0.8.1 起，Codex、Grok 自行决定是否使用原生子代理，Moose 无额外开关或强制委派提示；可展开活动查看返回结果，历史会保存。子代理实际执行时会使用底座模型额度。0.8.0 安装包仍包含旧开关。详见[原生能力与当前缺口](providers/native-capabilities.md)。
- 附件支持选择、拖放与粘贴图片，最多 10 个文件，每个 20 MB。图片取决于模型能力，视频不支持。Grok 1.0.30 ACP 未提供图片支持。
- Codex 支持请求批准、帮我批准、完全访问；Grok 支持请求批准和完全访问；Pi 仅支持完全访问，没有内置审批沙箱。扩展提问不等于全局工具审批。
- 审阅显示全部已暂存、未暂存、未跟踪改动，包含原有改动；不是当前代理的独占修改清单。预览有大小上限，二进制文件单独标识。
- 用量面板展示代理实际提供的上下文和套餐信息，不推算缺失额度。Pi 没有套餐额度接口。

## 原生计划（0.8.0 起）

Codex 输入 `/plan` 并在候选菜单选择计划模式，再输入任务。生成的原生计划卡片支持“修改计划”；保存后版本递增。审阅完成，点击“批准并执行”，Moose 将当前版本交回同一原生会话执行，并恢复原先的权限档位。若底座先提出澄清问题，回答后继续规划。

计划完成不会自动运行排队消息。若队列已有其他输入，先移除或处理它们，再批准计划。已批准版本不能再次批准；执行失败后可查看同一会话的错误并通过新消息继续。Grok 和 Pi 暂无此流程。

## 配置与扩展（0.11.0 起）

选中项目或会话后，点击顶部拼图图标。Codex 支持查看配置来源、修改用户级默认模型、MCP／插件开关、插件安装卸载和 MCP OAuth。新增 HTTP／STDIO MCP 时先预览，保存后保持禁用，再单独启用。用户级修改影响其他项目，活动任务期间暂不能修改配置。Hooks 当前只读，Grok／Pi 继续使用各自 CLI 管理。详见[第五阶段验收](providers/phase-five-testing.md)。

## 后台命令与定时任务（0.11.0 起）

点击顶部终端图标，在当前项目或会话目录运行本地 Shell 命令，查看文本输出、发送输入或停止。命令由 Moose 管理，使用本机用户权限；尚不支持 vim 等全屏终端程序。

定时任务支持命令或代理消息，单次或固定间隔执行。代理消息沿用绑定会话的底座、模型和权限，可能消耗模型额度。创建前可预览；暂停后可编辑，保存后仍需单独恢复。已排队或运行的任务需先结束，已触发的单次任务不能再次激活。

关闭窗口继续运行，退出应用后不执行。错过的周期最多合并补跑一次；失败或结果不确定时暂停。重启先核对命令结果和已有队列，避免自动重复。详见[第六阶段验收](providers/phase-six-testing.md)，内含无需模型 token 的手动测试。

## 快捷键与数据

| 快捷键 | 功能 |
| --- | --- |
| ⌘O | 打开项目文件夹 |
| ⌘N | 新建会话 |
| ⌘K | 搜索 |
| ⌘B | 收起 / 展开侧栏 |
| ⌘U | 用量面板 |
| ⌘, | 设置 |
| Enter / Shift+Enter | 发送 / 换行，输入法组合期间不发送 |
| ⌘Q | 取消运行并退出 |

关闭窗口后任务继续。历史、草稿、队列、附件保存在本机 userData：正式版为 `~/Library/Application Support/Moose`，开发版为 `~/Library/Application Support/Moose Dev`。重启可查看历史，未完成任务标记中断，不自动重发。代理使用时仍需连接其模型服务，本地客户端不等于离线推理。
