# 面试材料怎么读

项目说明按 **Moose 0.21.2** 的源码与验收更新（2026-09-30）。这组文档分为项目经历和通用练习；示例方案、他人经验与 Moose 已实现能力分别说明，不互相充当证明。

| 你现在要做什么 | 读哪份 | 读到什么程度 |
| --- | --- | --- |
| 准备项目介绍 | [项目面试指南](project-interview-guide.md) | 能讲用途、职责和一条任务链路，再选择两处难点 |
| 回答“为什么这样设计” | [项目追问资料](project-interview-reference.md) | 按问题查阅，顺着源码说明失败路径和验证范围 |
| 练前端与 AI 应用基础 | [题目](questions.md) → [答案](answers.md) | 先自己回答，再用答案查缺；每题可直接跳转 |
| 练现场代码审查 | [React 搜索组件](react-search-results-code-review.md) | 说清错误现象、出现顺序、修复与复现方法 |
| 准备 Agent／Skill 专题 | [追问备忘](agent-skill-interview-retrospective.md) | 理解通用设计，不把假设参数或他人数字当成项目事实 |

建议第一轮只做三件事：读简明指南，用“修登录按钮”画出任务链路，再选一个失败案例讲清。第二轮才读适配协议、Plan、worktree 等细节；通用题按岗位补充，不需要先背完 84 题。

阅读时留意三组容易混淆的概念：

- **请求受理、任务开始、任务结束**是三个时刻。发送接口返回，不代表模型已完成。
- **界面重连、原生会话续接、活进程恢复**是不同能力。能读回聊天，不代表死亡的 Shell 能复活。
- **方案示例、自动测试、真实系统验收**有不同证据范围。模拟权限拒绝不能证明点过系统授权弹窗。

日常操作查[使用指南](../usage.md)，当前功能支持查[能力表](../providers/native-capabilities.md)，测试条件查[测试与验证](../testing.md)。这些主文档负责事实，面试材料解释问题与取舍。历史性能数字保留版本和测量条件，不用旧结果代表新版本。
