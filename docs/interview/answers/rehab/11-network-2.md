# 十一、浏览器怎么认你 · 下

> 承接 [上篇](11-network-1.md)。对应原题 33、34、64、65。

上篇把请求发出去了，也说了失败怎么重试。请求到了另一台机器上，浏览器还要决定：脚本能不能读那份响应，下次访问带不带上你的登录，扫码的那张图是不是凭据，域名改了为什么不会立刻生效。这四件按「名字怎么变成一次被认出的访问」往下接。

## 先分清能不能显示，和能不能读到内容

同源指协议、域名、端口都相同。同源策略限制脚本去读另一个源的响应内容。它不禁止页面加载一切跨源资源。

另一台主机上的同一张图片，`<img>` 通常可以显示。`fetch` 之后读取内容，需要对方用 CORS 允许当前页的源。画进 Canvas 再读像素，还要满足跨源图片的读取条件，否则画布被污染，读像素会失败。`<img>`、样式表、经典的 `<script>` 可以直接引用 CDN。模块脚本、字体、Canvas 像素另有跨源限制。

CORS 是服务端明确授权「这个源可以读我的响应」，常见响应头是 `Access-Control-Allow-Origin`。没有这层授权，`fetch` 读跨源内容会失败，尽管一张图可能已经把同一 URL 显示出来了。

CSP 是站点自己声明允许从哪些地址加载资源。它可能直接拦住 CDN，即使同源策略本允许嵌入。两套规则叠在一起。图片能显示，也不等于能拿到完整的资源计时。计时细节还要 `Timing-Allow-Origin`，监控章已经说过。

**Moose：** Web 的页面和 API 由同一个本机服务提供。CSP 默认只允许加载本站资源。目前不依赖跨域 CDN。

## 读得到内容了，下次访问靠 Cookie 把你认出来

服务端用 `Set-Cookie` 告诉浏览器保存什么、何时过期、向哪里送。属性只出现在设置的时候。之后浏览器发出的 `Cookie` 请求头，通常只带名称和值。

`Domain` 决定哪些域名会收到。不设就只属于当前主机。`Path` 决定哪些路径下的请求会带上。`Expires` 和 `Max-Age` 是过期时间或有效秒数。都不设就是会话 Cookie，会话结束即失效。`Secure` 表示只在 HTTPS 下发送。`HttpOnly` 表示 JS 不能用 `document.cookie` 读到。`SameSite` 决定跨站请求带不带，取值有 `Strict`、`Lax`、`None`。`Partitioned` 按顶层站点分区存放，用于第三方嵌入。

`HttpOnly` 只禁止脚本读取。浏览器在符合规则的请求里仍会自动带上。`Path` 不是安全隔离，不要指望靠路径挡住同一站点上的其他页面。

有共同父域时，`Domain=example.com` 可以让 `a.example.com` 和 `b.example.com` 都收到。`a.com` 和 `b.com` 这种无关域名不能共享同一个 Cookie。跨站登录的做法是：统一身份服务完成跳转，各站点再各自建立自己的会话。

跨站还受浏览器隐私策略影响。Safari 和 Firefox 默认就会拦截或隔离第三方 Cookie。不要说「所有浏览器已经彻底移除了第三方 Cookie」，策略并不相同。`SameSite=None` 必须同时带 `Secure`。`Partitioned` 让嵌入场景下的 Cookie 按顶层站点隔开，具体效果以各浏览器为准。

跨源请求若要带 Cookie，前端要打开凭证，例如 `fetch` 的 `credentials: 'include'`，服务端也要返回允许凭证的 CORS 头。只加一边是不够的。不设过期，是会话期。不设 `Domain`，是当前主机。两件独立。

```http
Set-Cookie: moose_session=<随机值>; HttpOnly; SameSite=Strict; Path=/; Secure
```

**Moose：** Web 的 `moose_session` 没有设置 `Domain`，是当前主机的 Cookie，没有做跨子域共享，也没有设置过期时间。通过 HTTP 访问时不会设置 `Secure`。之后的请求只带回 `Cookie: moose_session=<随机值>`，后台再检查这个值是不是有效会话。

## Cookie 能维持一次会话，扫码不能把长期凭据画进二维码

电脑上的网页要登录，手机已经登录了同一个账号。如果二维码直接等于长期凭据，被人拍照就能冒用。它只应该让手机找到「这台电脑正在等的那一次登录」。

电脑向服务端申请扫码会话。服务端给出不可预测、短期、一次性的标识。电脑把标识画成二维码，里面没有长期凭证。已登录的手机扫码，展示将要登录的设备，用户点确认。服务端记下授权。电脑用轮询或推送得知结果，再建立电脑自己的登录会话。会话要过期、只能用一次，并绑定发起请求的那台电脑。否则一个二维码可以被另一台机器拿去完成登录。

长期凭证在用户确认之后，发给电脑自己的会话。这和上一节的 Cookie 接上：二维码不是 Cookie，确认之后电脑才有自己的会话 Cookie。

**Moose：** 当前没有扫码登录。上面是设计方案，不是项目功能。

## 会话建好了，域名还得先变成地址，改了也不会立刻全球生效

浏览器拿到网址后，要先知道域名对应哪个网络地址，才能建立连接。DNS 只负责找地址，不负责网址后面的路径。路径、Cookie、TLS 都在连上之后。

A 记录给出 IPv4 地址。AAAA 记录给出 IPv6 地址。CNAME 表示这个名字是另一个域名的别名，还要再解析那个名字。

查找会经过浏览器、操作系统、递归解析器（运营商或公共 DNS）这几层缓存。没有命中时，递归解析器再去问权威 DNS，并按 TTL 缓存。TTL 是这条记录建议的缓存时长。CDN 可以借助解析策略，把用户指到较近或较空闲的节点。所以同一个域名在不同网络里解析出的 IP 可以不同。

因为有多层缓存，改了域名解析之后，不会立刻对所有人生效。还没过期的缓存会继续用旧地址。

这一题的答案没有写 Moose 的 DNS 配置。不要把通用解析过程说成项目里的实现。
