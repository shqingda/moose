## 27. 如何实现预览 PDF 文件

> **这题在考什么**：“预览 PDF”可能只要求用户能打开看，也可能要求统一的页码、搜索和标注。面试官想看你能否根据需求选方案，并考虑鉴权、大文件和资源释放等细节。

**一句话回答**：只需点开查看就用浏览器自带的 PDF 查看器；要求统一的页码、搜索和标注时再考虑 PDF.js 自己渲染。

**展开说明**
- 浏览器内置 PDF 查看器成本最低，用 `iframe` 或新页签打开即可，但各浏览器界面不统一，也难以定制。
- PDF.js 是 Mozilla 开源的 PDF 渲染库，可以完全控制界面，实现统一的页码、搜索和标注，代价是开发和维护成本更高。
- 需要鉴权的文件，应通过受控的地址或带凭证的请求获取。如果用 Blob URL（`URL.createObjectURL` 生成的临时地址）展示，关闭预览时要调用 `URL.revokeObjectURL` 释放内存。
- 大文件只渲染可见的页面。
- 还要处理跨域、Range 请求（按字节范围分段下载）、字体缺失，以及扫描件没有可选文字等问题。

| 方案 | 适用场景 | 代价 |
| --- | --- | --- |
| 浏览器内置查看器 | 只需点开查看 | 界面不统一，难定制 |
| PDF.js | 需要统一的页码、搜索、标注 | 开发和维护成本高 |

**Moose 里的做法**：Moose 对 PDF 提供经过认证的下载和另存，不内嵌 PDF 渲染器；图片、文本和代码另有受控预览。

## 28. 如何在划词选中的文本上添加右键菜单？富文本编辑器里的划词又是怎么做的？
*（合并了原第 28、29 题）*

> **这题在考什么**：划词指用鼠标拖动选中一段文字再对它操作。普通网页里，用户选中一句话后点右键，希望出现“复制”“解释”等自定义菜单；富文本编辑器还要知道这段文字对应文档数据里的哪个位置，否则 DOM 一重排，评论和加粗就会落到错误的文字上。面试官想看你会用 Selection 和 Range 读取选区，并理解浏览器选区和编辑器文档模型之间的关系。

**一句话回答**：浏览器用 Selection 和 Range 表示划词；自定义右键菜单在 `contextmenu` 里读取选区，确认非空且完全在目标区域内才显示，并先保存文字和位置；富文本编辑器再把 DOM 位置映射成自己文档模型里的位置，所有操作都通过修改模型完成。

**展开说明**
- 浏览器用 `window.getSelection()` 拿到 Selection（当前选区），再取出其中的 Range（一段连续选中范围）。Range 由“起点节点加偏移量、终点节点加偏移量”描述，可以跨越多个标签。
- 自定义右键菜单：在目标区域监听 `contextmenu`（右键菜单事件），只有选区非空、且起点和终点都在目标区域内，才阻止默认菜单并显示自己的菜单。
- 菜单坐标可以取鼠标位置，也可以取选区的矩形位置，并限制在视口内。支持按 Escape 关闭，并提供键盘入口。
- 点击菜单或工具栏按钮可能让选区消失，所以在弹出菜单、点击按钮之前就保存所需的文字和位置。
- 富文本编辑器内部有自己的文档模型（描述内容和格式的数据结构），需要把 DOM 位置映射成模型中的位置。加粗、评论等操作修改模型并进入撤销历史，而不是直接拼接 `innerHTML`。
- 文档内容变化后，已有的标注还要能重新定位到正确的文字上。

**示例**：下面的关键代码先确认选区确实属于目标区域，再保存选中的文字。

```ts
const selection = window.getSelection();
const range = selection?.rangeCount ? selection.getRangeAt(0) : null;
// 没有选区、选区为空、或不在目标区域内，都不显示菜单
if (!range || range.collapsed || !root.contains(range.commonAncestorContainer)) return;
const selectedText = selection!.toString(); // 先保存文字，防止点菜单后选区丢失
```

**容易答错的地方**
- 如果内容之后会变化，持久标注不能只保存旧的 DOM Range，因为 DOM 变化后它会失效或指向错误位置；应保存模型中的位置或文字锚点。
- 不能直接拼 `innerHTML` 来实现格式操作，这样绕过了模型和撤销历史。

## 36. 前端如何实现折叠面板效果？

> **这题在考什么**：设置页、FAQ、日志详情都常用折叠面板。面试官想看你除了“切换显示隐藏”，是否还会考虑语义、键盘操作和无障碍。

**一句话回答**：普通折叠优先用原生 `<details><summary>`；需要手风琴或受控状态时，用按钮控制面板，并同步 `aria-expanded` 和 `aria-controls`。

**展开说明**
- 折叠面板看起来只是显示或隐藏内容，但标题能否用键盘操作、收起后里面的按钮还能不能被聚焦，也属于实现的一部分。
- `<details><summary>` 是浏览器原生的折叠元素，自带基本语义和键盘操作，不需要额外写 JS。
- 需要“同时只展开一项”的手风琴效果，或由外部状态控制展开时，用 `<button>` 做标题。用 `aria-expanded` 告诉读屏软件当前是否展开，用 `aria-controls` 指向被控制的面板。
- 加展开动画时，要照顾用户系统里“减少动态效果”的偏好（`prefers-reduced-motion`）。

**示例**：不需要受控状态时，下面这段原生 HTML 就能实现折叠：

```html
<details>
  <!-- 点击或按键即可展开/收起 -->
  <summary>工具调用详情</summary>
  <pre>执行结果…</pre>
</details>
```

**Moose 里的做法**：Moose 的工具调用记录和思考记录用 `details/summary` 折叠。

**容易答错的地方**
- 收起后的内容不能还能被 Tab 键聚焦到，否则键盘用户会“跳进”看不见的区域。

## 37. dom 里面，如何判定 a 元素是否是 b 元素的子元素

> **这题在考什么**：做“点击外部关闭弹窗”这类功能时，要判断点击的目标是否在弹窗内。面试官想看你是否分清“直接子元素”和“任意层级后代”，并知道对应的 API。

**一句话回答**：判断 a 是否在 b 内部用 `b.contains(a)`；要排除 a 就是 b 本身，加上 `a !== b`；只判断直接子元素用 `a.parentElement === b`。

**展开说明**
- 先问清题意：“子元素”可能指直接下一层，也可能指任意深度的后代。关系不同，方法也不同。
- `b.contains(a)` 判断 a 是否是 b 的后代，但 a 和 b 是同一个节点时也返回 `true`。
- 要求严格后代时写 `b.contains(a) && a !== b`。
- 只判断直接子元素时，比较 `a.parentElement === b`。
- 在 Shadow DOM（组件内部被封装隔离的 DOM 树）中处理事件时，普通的包含判断可能不准。这时应查看事件的 `composedPath()`，它返回事件经过的完整节点路径，包括 Shadow DOM 内部的节点。

| 需求 | 写法 |
| --- | --- |
| 任意层级后代（含自身） | `b.contains(a)` |
| 严格后代 | `b.contains(a) && a !== b` |
| 直接子元素 | `a.parentElement === b` |

**容易答错的地方**
- `contains` 对自身也返回 `true`，不能直接当作“严格子元素”来用。

## 41. flex:1 代表什么

> **这题在考什么**：两栏布局里，常见写法是左侧固定、右侧 `flex: 1` 占满剩余空间，但长内容经常把布局撑破。面试官想看你是否理解 `flex: 1` 的真实含义，以及为什么常要配合 `min-width: 0`。

**一句话回答**：`flex: 1` 通常等价于 `flex: 1 1 0%`，表示元素可以增长、可以收缩，并以 0% 作为基础大小来分配剩余空间。

**展开说明**
- Flex 布局先看所有子项的基础大小，再分配多出来或不够的空间。`flex: 1` 改变的是这套分配规则，而不是给元素写一个固定宽度。
- 三个值分别是 `flex-grow: 1`（有多余空间时可增长）、`flex-shrink: 1`（空间不够时可收缩）和 `flex-basis: 0%`（从 0 开始分配）。
- 几个子项都写 `flex: 1` 时，通常会平分可分配的空间。
- Flex 子项默认的最小尺寸是内容本身的大小，长文本或宽表格仍可能把布局撑开。横向布局里常加 `min-width: 0`，纵向滚动容器里常加 `min-height: 0`，允许它缩到比内容更小，再交给 `overflow` 滚动。

**示例**：下面是左侧固定宽度、右侧占满剩余空间并可滚动的写法：

```css
/* 侧栏：不增长、不收缩，固定 240px */
.sidebar { flex: 0 0 240px; }
/* 主区：占满剩余空间；min-width: 0 允许被长内容压缩，超出部分滚动 */
.transcript { flex: 1; min-width: 0; overflow: auto; }
```

**Moose 里的做法**：Moose 的消息区域使用 `min-height: 0`，保证它能够正常滚动。

**容易答错的地方**
- `flex: 1` 不等于“每一项都占满父容器”，而是参与分配剩余空间。

## 49. [React]循环渲染中为什么推荐不用 index 做 key

> **这题在考什么**：渲染列表时 React 要求给每一项设置 key，很多人图省事直接用数组下标。面试官想看你是否理解 key 的作用，以及下标做 key 在插入、删除时会出什么问题。

**一句话回答**：React 用 key 判断“哪一项还是原来那一项”；用 index 做 key 时，列表一插入或删除，组件状态就可能跟着下标错位到别的记录上。

**展开说明**
- 每次重新渲染时，React 会根据 key 把新旧列表里的项对应起来，key 相同就复用原来的组件和它的内部状态。
- 假设在列表第一行插入一条新消息，原来的第二行就变成第三行。如果 key 是下标，React 会把“旧第二行”的组件状态留给新的第二行。
- 于是输入框里的内容、展开状态等，会跟着行号跑到另一条记录上。
- 应该优先使用稳定的业务 ID 做 key。

**示例**：下面两行对比了用下标和用业务 ID 做 key 的区别：

```tsx
// 用下标：插入一条后，组件身份和消息错位
messages.map((message, index) => <Row key={index} message={message} />)
// 用业务 ID：组件身份始终跟着消息走
messages.map((message) => <Row key={message.id} message={message} />)
```

**Moose 里的做法**：Moose 的消息时间线用 `message.id` 做 key。流式更新时只修改消息内容，不改变消息的身份。

**容易答错的地方**
- 不要每次渲染都生成随机 key。这样每一项都会被当成新元素，状态会丢失，性能也会变差。

## 50. [React]如何避免使用 context 的时候，引起整个挂载节点树的重新渲染

> **这题在考什么**：Context 能把数据传给很深的子组件，但值一变，读取它的组件都会更新。面试官想看你如何防止高频变化的数据牵动大片无关组件。

**一句话回答**：把高频状态和低频设置拆成不同的 Context，让 Provider 只包住需要它的范围，并保持传入对象和函数的引用稳定；更细粒度的订阅用 selector store。

**展开说明**
- Context 的值一变，所有读取它的组件都要重新渲染。问题不在“读取的组件会更新”，而在于高频数据会牵动不相关的组件。
- 把高频状态（如输入中的文字）和低频设置（如主题、语言）拆到不同的 Context 里。
- Provider 只包住真正需要这份数据的子树，不要都放在应用根节点。
- 传给 Provider 的对象和函数，按需用 `useMemo`、`useCallback` 保持引用稳定。否则父组件每次渲染都会生成新对象，导致所有消费者更新。
- 需要更细粒度订阅高频数据时，可以用 selector store（如 Zustand），组件只订阅自己用到的那一小块。

**Moose 里的做法**：Moose 的 LocaleContext 只管理语言。切换语言时，所有文案跟着更新，这是正常且符合预期的结果。

**容易答错的地方**
- `memo` 挡不住组件自己读取的 Context 的更新。只要组件里调用了 `useContext`，值一变它就会重新渲染。

## 60. 站点一键换肤的实现方式有哪些？

> **这题在考什么**：深色模式、品牌主题都需要“一键换肤”。面试官想看你是否会用 CSS 变量统一管理颜色，并处理好跟随系统、首屏闪白和对比度这些细节。

**一句话回答**：用语义化的 CSS 变量定义背景、文字、边框等颜色，在根节点切换 `class` 或 `data-theme`，组件只引用变量；保存用户的选择，system 模式下跟随系统外观。

**展开说明**
- 换肤要改的不只是页面背景，文字、边框、焦点状态和图表颜色都要一起变。如果颜色写死在每个组件里，很难保证一致。
- 按语义定义 CSS 变量，例如 `--surface` 表示面板背景、`--text` 表示正文颜色，而不是按色值命名。
- 在根节点切换 `class` 或 `data-theme` 属性，组件只引用变量，不直接写颜色。
- 保存用户选择；system 模式通过 `prefers-color-scheme` 媒体查询跟随系统外观。
- 在页面首次显示之前就应用主题，避免先白后黑的闪烁；同时检查文字对比度、焦点样式和图表颜色。

**示例**：下面的 CSS 演示组件只依赖颜色语义，切换 `data-theme` 即可换肤：

```css
/* 默认（浅色）主题 */
:root { --surface: #fff; --text: #111; }
/* 深色主题只覆盖变量值 */
[data-theme='dark'] { --surface: #171717; --text: #eee; }
/* 组件只引用变量，不写死颜色 */
.panel { background: var(--surface); color: var(--text); }
```

**Moose 里的做法**：Moose 提供 system、light、dark 三种主题，用户的手动选择优先于系统设置。
